# Deck Input Lift 0.1.1

[English](README.md) · [v0.1.1 다운로드](https://github.com/www622846/deck-input-lift/releases/tag/v0.1.1) · [버그 제보](https://github.com/www622846/deck-input-lift/issues)

Steam Deck **데스크톱 모드**에서 Steam 키보드가 열리면 사용 중인 창을 키보드 위
공간에 맞추고, 닫히면 원래 위치·크기로 복원하는 초기 구현입니다. 위쪽으로 옮긴
키보드는 아래쪽 공간을 사용합니다. 기존 키보드와 한글 입력기를 그대로 사용합니다.

**현재 상태: Steam Deck의 KWin 6.7.3 Wayland에서 한국어 Steam 키보드 인식과 창 축소·복원을 확인했습니다.**
Firefox 152.0.4 Flatpak에서도 실제 Steam 키보드를 열고 닫아 원래 입력칸의 자동 스크롤,
입력 문자열 유지, 창 크기 복원을 확인했습니다. 별도 브라우저 확장 없이 동작합니다.
KWin 5/6 API를 지원하도록 작성했지만 다른 SteamOS/Steam 버전별 호환성은 실기 확인이 필요합니다.
게임 모드용 Decky 플러그인이 아닙니다.

## 설치

1. 릴리스에서 [deck-input-lift-0.1.1.zip](https://github.com/www622846/deck-input-lift/releases/download/v0.1.1/deck-input-lift-0.1.1.zip)을 스팀덱에 내려받아 압축을 풉니다.
2. Steam 키보드를 닫은 뒤 압축을 푼 `deck-input-lift` 폴더에서 터미널을 열고 실행합니다.

   ```bash
   bash install.sh
   ```

3. 브라우저 검색창을 누르고 `Steam + X`로 키보드를 엽니다. 창 아래쪽이 키보드 위에
   맞춰지는지 확인합니다. 키보드를 닫으면 창이 돌아옵니다.

`sudo`, 시스템 읽기 전용 해제, Decky 설치가 필요하지 않습니다. KDE 사용자 폴더에만
설치합니다. Python D-Bus·PyGObject·AT-SPI가 있으면 데스크톱 자동 실행 스크롤 보조 기능도 설치합니다.
검증한 스팀덱에는 이 의존성이 이미 설치돼 있어 새 시스템 패키지는 필요하지 않았습니다.
설치 후 작동하지 않으면 시스템 설정 → 창 관리 → KWin 스크립트에서
**Deck Input Lift**를 켜고 적용합니다. 업데이트 후에는 키보드를 닫고 로그아웃/로그인합니다.

시스템 설정 → 창 관리 → KWin 스크립트 → 파일에서 설치에서
`dist/deck-input-lift.kwinscript`를 선택할 수도 있습니다. 이 방식은 창 크기 조절만 설치하므로,
입력칸 스크롤 보조 기능까지 사용하려면 `install.sh`로 설치하세요.

## 입력칸 자동 스크롤: 시스템 Focus Guard

KWin에서 키보드가 열린 것을 알리면 시스템 AT-SPI 접근성 API로 포커스된 원래
입력칸을 화면 안에 스크롤합니다. 입력값·비밀번호·클립보드를 읽지 않으며 키 입력도 수집하지 않습니다.
Flatpak에서는 창과 접근성 프록시의 프로세스가 다를 수 있어 `.flatpak-info`의 고유 인스턴스 ID로
같은 앱을 연결합니다. `.env` 파일이나 프로세스 환경은 읽지 않습니다.

이 서비스는 데스크톱 세션에서 실행되며, 키보드가 닫히면 스크롤 요청도 멈춥니다.
AT-SPI에서 편집 가능한 요소를 제공하고 `ScrollTo`를 구현한 앱에서 작동합니다.
브라우저 확장 설치나 Firefox 서명 확인 설정 변경이 필요하지 않습니다.

## 대체 보조 확장: 브라우저 Focus Guard

창 높이만 줄이면 브라우저 주소창은 보이지만, 일부 웹페이지는 포커스된 입력칸을
줄어든 화면 안으로 스크롤하지 않습니다. 시스템 Focus Guard를 사용할 수 없는 환경에서는
`browser/`의 보조 확장을 대신 사용할 수 있습니다.
화면 높이 변경 또는 입력칸 포커스를 감지해 **원래 입력칸**을 화면 안으로 스크롤합니다.
별도 입력창에 복사하지 않으므로 한글 조합·자동완성·사이트 입력 이벤트를 그대로 사용합니다.

- **Chrome/Chromium**: `chrome://extensions` → 개발자 모드 → 압축해제된 확장 로드 → `browser` 폴더.
- **Firefox**: `about:debugging#/runtime/this-firefox` → 임시 부가 기능 로드 → `browser/manifest.json`.
  Firefox 임시 설치는 재시작하면 사라집니다. 상시 배포에는 Mozilla 서명이 필요하며 아직 등록하지 않았습니다.
- 확장을 설치하기 전에 열려 있던 탭은 새로고침합니다.

확장은 HTTP/HTTPS 페이지에서 입력 요소의 **위치만** 확인하며 입력 내용이나 비밀번호를 읽거나
저장·전송하지 않습니다. 브라우저 내부 페이지, 브라우저가 확장을 차단하는 페이지,
닫힌 Shadow DOM에는 적용되지 않습니다. 브라우저 주소창은 KWin의 창 크기 조절로 대응합니다.
이 확장만 설치하면 Steam 키보드의 겹침을 감지할 수 없으므로 KWin 스크립트와 함께 사용해야 합니다.

## 일시 중지 및 제거

- `Meta + Ctrl + K`: 동작 중지와 창 복원 / 다시 시작.
- 물리 키보드가 없다면 Steam 키보드를 닫아 창을 복원한 뒤, KWin 스크립트 설정에서 끕니다.
- 제거: Steam 키보드를 먼저 닫은 뒤 `bash uninstall.sh`. 브라우저 확장은 별도로 제거합니다.
- 보조 서비스 상태: `systemctl --user status deck-input-lift-focus.service`.
- 스크립트가 중단된 상태에서 창이 작게 남으면 창을 최대화하거나 크기를 직접 조절하면 됩니다.

## 제한과 실기 확인 항목

- Steam 키보드가 KWin에서 관리하는 독립 창으로 보여야 합니다. 이름이 바뀌거나
  Wayland 레이어 표면으로만 표시되는 버전에서는 인식하지 못할 수 있습니다.
  기본 인식 제목은 `Steam Input On-screen Keyboard`, `Steam Input 가상 키보드`, `Steam Keyboard`이며 Steam 클래스도 검사합니다.
- 키보드를 열기 전에 브라우저/앱에 포커스를 둡니다. 스크립트 활성화 시 이미 키보드가
  포커스를 가진 경우 키보드를 닫았다 다시 엽니다.
- 앱 최소 높이보다 남는 공간이 작으면 변경하지 않습니다. 앱이 최소 크기를 강제하거나
  입력칸 자체가 스크롤되지 않는 구조면 가시성을 완전히 보장할 수 없습니다.
- 최대화 상태를 읽을 수 있는 KWin에서는 해당 상태를 사용합니다. 구버전은 상태 신호를 추적하고,
  처음 보는 창은 작업 영역과 크기를 비교해
  추정하므로 수동으로 화면 크기에 맞춘 창이 최대화로 복원될 수 있습니다.
- 특히 Wayland에서는 비동기 크기 변경 때문에 **최대화 이전의 일반 창 크기** 복원이
  정확하지 않을 수 있습니다. 타일링 스크립트와의 동시 사용도 실기 검증 전입니다.
- 키보드가 열린 동안 모니터를 분리하면 복원을 시도합니다. 복잡한 모니터 배치 변경 후에는
  창을 다시 화면 안으로 옮겨야 할 수 있습니다.
- Android처럼 모든 앱의 커서 위치를 시스템 차원에서 추적하는 완성형 입력기 구현은 아닙니다.

실기에서 Firefox의 긴 페이지 아래 검색 입력칸과 최대화 창을 검증했습니다.
Google/Naver 등 개별 사이트, 실제 한글 IME 조합·삭제·Enter 제출, 상단 키보드,
다양한 디스플레이 배율과 다른 앱은 추가 확인이 필요합니다.

## 개발 및 검증

외부 패키지 설치 없이 Node.js 18+와 Python 3으로 실행합니다.

```bash
npm test
npm run build
```

테스트는 KWin 이벤트를 흉내 낸 환경에서 창 축소·복원·전환·모니터·숨김·전체 화면을
검사하고, 브라우저 보조 코드가 입력 내용을 읽지 않으며 필요한 요소에만 스크롤을
요청하는지 확인합니다. JavaScript 테스트 29개와 Flatpak 프로세스 연결 회귀 테스트 8개가 통과했습니다.

실제 Chrome 통합 검증도 수행했습니다. 1280×420 크기의 headless Chrome에서 중첩 스크롤
영역 아래의 검색창·textarea·비밀번호·contenteditable 입력칸 4개가 화면 안에 들어오고,
한글 문자열이 바뀌지 않으며 새 input 이벤트가 발생하지 않는 것을 확인했습니다.
별도로 Steam Deck의 실제 KWin/Steam 키보드에서 창 축소·복원을 확인했습니다.
Firefox 입력칸 보조 기능까지 통합 검증을 통과했습니다. 실제 한글 IME 조합 과정은 별도 확인이 필요합니다.
수치와 검증 범위는 [VERIFICATION.md](VERIFICATION.md)에 정리했습니다.

브라우저 통합 검증 재실행:

```bash
python3 tests/browser-integration.py --chrome /path/to/chrome
```

설치 파일은 허용한 파일 목록으로만 패키징합니다. `.env`는 읽거나 포함하지 않습니다.
GitHub 검색 결과와 참고 자료는 [RESEARCH.md](RESEARCH.md)에 있습니다. 소스와 배포 파일은 [공개 저장소](https://github.com/www622846/deck-input-lift)에서 확인할 수 있습니다. 라이선스는 [MIT](LICENSE)입니다.
